                                 Abstract

Retrieval-Augmented Generation (RAG) has become a key paradigm for

enhancing factual reasoning in large language models (LLMs). However,

conventional RAG systems suffer from structural limitations such as

retrieval bottlenecks, evidence misalignment, and lack of scalability in

multi-agent environments [1], [3], [5]. Meanwhile, recent multi-agent

orchestration frameworks enable modular reasoning and task distribution

but lack a standardized communication protocol to ensure context

synchronization and traceability [7], [24]. These limitations hinder the

realization of efficient and interpretable General Multi-Agent Reasoning.

This study proposes an optimized architecture that integrates the Model

Context Protocol (MCP) to enhance communication efficiency and context

consistency among agents, building upon the hierarchical retrieval

structure of the existing DocsRay [16] framework. The proposed framework

converts pseudo-Table-of-Contents (pseudo-TOC) information extracted by

DocsRay into a standardized MCP message schema, ensuring state

synchronization between the Retriever and Verifier agents. This approach

mitigates data bottlenecks compared to conventional simple connection

methods and secures traceability throughout the reasoning process.

Furthermore, this study introduces the Context Consistency Score (CCS) as

a semantic coherence metric between retrieved evidence and generated

responses, and further defines a CS-Index that integrates CCS with end-to-

end context synchronization latency. This combined metric quantitatively

evaluates how effectively a multi-agent system preserves contextual

quality while delivering responses in a time-efficient manner.



                                    7
Through comprehensive experiments conducted on three benchmark datasets,

including MMLongBench-Doc [31], SlideVQA [32], and M3SciQA [33], the

proposed RAG-MCP integrated architecture demonstrates superior efficiency

in resource-constrained environments. This is achieved by significantly

reducing the Context Synchronization Latency compared to conventional

single-agent methods, while maintaining stable performance even with a 4-

billion-parameter (4B) scale lightweight model. This study is significant

not merely for proposing a new RAG algorithm, but for presenting a unified

architecture that maximizes the operational efficiency of existing

document reasoning models.

Keywords: Retrieval-Augmented Generation (RAG), Model Context Protocol

(MCP), Context Synchronization, Object-Oriented Multi-Agent, On-Device

General Multi-Agent Reasoning

                            국문 초록

Retrieval-Augmented Generation(RAG)은 대규모 언어모델(LLM)의 사실적 추론을

강화하기 위한 핵심 기술로 자리 잡았으나, 기존 RAG 기반 시스템은 검색

효율성 저하, 근거 불일치, 그리고 멀티에이전트 환경에서의 확장성 부족이라는

구조적 한계를 갖는다. [1], [3], [5]. 한편, 최근 주목받는 멀티에이전트

오케스트레이션 프레임워크는 역할 분담과 모듈화된 추론을 가능하게 하지만,

공유 문맥 동기화 및 추론 추적성(traceability)을 보장하는 표준화된 통신

프로토콜이 부재하다 [7], [24]. 이러한 한계는 효율적이고 해석 가능한 범용

멀티에이전트 추론(General Multi-Agent Reasoning) 구현을 어렵게 만든다.

본 연구는 기존 Docsray [16] 프레임워크의 계층적 검색 구조를 기반으로,

에이전트 간 통신 효율성과 문맥 일관성을 강화하기 위해 Model Context

Protocol(MCP)을 통합한 최적화된 아키텍처를 제안한다. 제안된 프레임워크는

DocsRay [16]가 추출한 의사 목차(pseudo-TOC) 정보를 MCP 의 표준화된 메시지

스키마로 변환하여 검색(Retriever)과 검증(Verifier) 에이전트 간의 상태

동기화를 보장한다. 이를 통해 기존의 단순 연결 방식 대비 데이터 병목 현상을

줄이고, 추론 과정의 추적성(Traceability)을 확보하였다. 또한, 본 연구는

검색된 근거와 생성된 응답 간의 의미적 정합성을 평가하는 CCS(Context

Consistency Score)를 정의하고, 이를 핵심 요소로 차용하여 최종 답변

생성까지의 엔드투엔드 문맥 동기화 지연 시간을 통합한 CS-Index 를

제안함으로써, 제안된 멀티에이전트 통합 구조의 신뢰성과 효율성을 동시에

검증하였다.

MMLongBench-Doc [31]과 SlideVQA [32], M3SciQA [33] 3 개의 벤치마크 실험

결과, 제안된 RAG-MCP 통합 구조는 기존 단일 에이전트 방식 대비 문맥 동기화

지연(Sync Latency)을 단축하고, 4B 규모의 경량 모델에서도 안정적인 성능을

유지함으로써 자원 제약 환경에서의 효율성(Efficiency)을 입증하였다.

제 1 절 연구의 배경 및 필요성

대규모 언어모델(Large Language Model, LLM)은 최근 자연어 처리, 코드 생성,

멀티모달 이해 등 다양한 분야에서 놀라운 추론력과 일반화 능력을 보여주었다.

그러나 범용 멀티에이전트 추론(General multi-agent reasoning)을 실현하기

위해 요구되는 문맥 확장성(Context Scalability), 사실 근거성(Factual

Grounding), 해석 가능성(Explainability) 측면에서는 여전히 한계가 존재한다.

[3], [5], [10]. 기존 General Multi-Agent Reasoning 프레임워크는 중앙

집중형 단일 LLM 구조에 의존하여, 지식을 순차적으로 처리하고 응답을

생성하는 방식이다. 이로 인해 계산 중복, 추론 불투명성, 비용 비효율성 등의

문제가 발생한다. 이를 보완하기 위해 제안된 Retrieval-Augmented Generation

(RAG) 구조 [1], [8], [11], [23], [25]는 외부 지식 검색을 통해 모델의

사실성을 향상시켰지만, 검색 병목(Retrieval Bottleneck)과 문맥

불일치(Context Inconsistency), 근거 정합성 부족(Evidence Alignment

Deficiency) 문제를 여전히 내포한다. 한편, AutoGen [7], TaskWeaver [24],

최근 Docsray [16]와 같은 계층적 문서 분석 모델은 긴 문서 처리에서 탁월한

성과를 보여주었다. 그러나 이러한 고도화된 RAG 시스템을 멀티에이전트

환경이나 온디바이스(On-Device) 시스템으로 확장할 때, 에이전트 간 비동기적

통신으로 인한 문맥 불일치(Context Inconsistency)와 높은 연산 비용 문제가

발생한다. RAG(Retrieval-Augmented Generation) 기술의 발전으로 문서를

구조적으로 이해하는 시도들이 이어지고 있다. 특히 Docsray [16]는 의사




                              11
목차(pseudo-TOC)를 활용한 계층적 검색을 통해 긴 문서 처리의 새로운 기준을

제시하였다. 하지만 Docsray [16]와 같은 고도화된 시스템이 멀티에이전트

환경으로 확장될 때, 각 모듈(OCR, Retriever, Generator) 간의 비표준화된

통신은 데이터 병목과 문맥 손실(Context Drift)을 유발하는 문제가 있다.

이에 본 연구에서는 Model Context Protocol(MCP) [28]을 기반으로 RAG 를

통합한 객체지향 멀티 에이전트 프레임워크(Multi-Agent Object-Oriented

Framework)를 제안한다. 본 구조는 PDTS(Progressive Domain Transfer

Strategy)의 점진적 적응 개념과 Docsray [16]의 계층적 문서

구조화(Hierarchical Context Organization) 아이디어를 결합하여, pseudo-

context indexing 기법을 통해 문서 및 멀티모달 데이터의 계층적 문맥 관리와

에이전트 간 적응적 추론을 실현한다. 특히, Retriever–Verifier–Generator

간의 상호작용을 MCP 표준 메시지 스키마로 통합함으로써, 재현 가능한

조정(Reproducible Coordination)과 검증 가능한 정보 흐름(Verifiable

Information Flow)을 보장한다.



제 2 절 연구의 목적

본 연구는 RAG 와 MCP 를 통합한 객체지향 멀티에이전트 프레임워크를 설계하여,

다음의 세부 목표를 달성하는 것을 목적으로 한다.

⑴ Docsray [16] 기반 시스템의 통신 최적화: 계층적 검색 결과를 MCP

  프로토콜로 캡슐화하여 에이전트 간 문맥 손실을 방지한다.

⑵ 자원 효율성(Efficiency) 입증: 대규모 모델(27B)이 아닌

  온디바이스급 경량 모델(4B)에서도 MCP 통합을 통해 Docsray 의 성능을

  효율적으로 재현할 수 있음을 보인다.

(3) 정량적 일관성 검증: CCS (Context Consistency Score) 지표를 통해

  통합된 프레임워크의 동작 안정성을 평가한다.

 나. MCP 기반 비동기 메시징 구조를 통해 에이전트 간 문맥 일관성과 동기화

 확장성을 확보하였다.

제 1 절 연구 통합 개요 (Overview of Research Integration)

본 연구는 범용 멀티에이전트 추론(General Multi-Agent Reasoning)의

효율적이며 해석 가능한 구현을 위해 네 가지 핵심 연구 축을 통합하였다.

첫째, Retrieval-Augmented Generation (RAG) 및 Dense Retrieval (DPR, FiD)

기반의 사실 추론 구조를 도입하여 LLM 의 환각(hallucination)을 억제하고 근거

기반 응답 생성을 가능하게 하였다 [1], [8], [11], [21], [22], [23], [25].

둘째, 선행 연구인 Docsray [16] 및 QueryDoc [16]의 구조 인식형 문서 파싱과

pseudo-TOC(의사 목차) 기반 계층적 검색 구조를 활용하여, 장문 및 멀티모달

문서 내 의미적 계층 관계를 반영하였다.

셋째, Model Context Protocol (MCP)을 통한 표준화된 멀티에이전트 조정

체계를 설계하여, 에이전트 간 문맥 동기화를 결정적(deterministic) 방식으로

수행할 수 있도록 하였다 [28].

넷째, Progressive Domain Transfer System (PDTS)을 도입하여 도메인 간 적응

학습과 자기검증(self-verifying) 학습 메커니즘을 확립하였다 [14]. 이 네

가지 연구 요소는 본 연구에서 제안하는 RAG–MCP 통합 객체지향 프레임워크로

결합되어, 제한된 자원 환경에서도 적응적·재현 가능한 General Multi-Agent

Reasoning 추론을 수행할 수 있는 기반을 제공한다. 이는 최근 주목받고 있는

자기검증(Self-Verifying), 자원적응(Resource-Adaptive), 재현

가능(Reproducible) Multi-Agent Reasoning 시스템 패러다임과 일치한다.

제 2 절 RAG 및 밀집 검색 (Dense Retrieval: DPR, FiD)

RAG [1]는 LLM 의 파라미터 기반 지식(parametric memory)과 외부 검색(non-

parametric retrieval)을 결합하여 응답의 사실성을 강화한다. DPR [21]은 듀얼

인코더 기반의 임베딩을 통해 문서 간 의미적 유사도를 효율적으로 계산할 수

있는 구조를 제시하였다.

또한 Fusion-in-Decoder [22]는 다중 문서 융합을 디코더 단계에서

수행함으로써 개방형 질의응답(Open-domain QA)에서의 성능을 향상시켰다.

이러한 기술들은 본 연구의 Retriever Agent 설계 기반을 이루며, 하이브리드

방식(Dense + Lexical)의 검색 기법과 pseudo-TOC 기반 계층 구조를 결합하여,

검색 정확도와 재현성을 균형 있게 확보한다.

Verification)

제 4 절 멀티에이전트 오케스트레이션과 MCP (Model Context Protocol)

AutoGen [7]과 TaskWeaver [24]는 멀티에이전트 협업 기반의 LLM 조정 가능성을

보여주었으나, 비정형적(heuristic) 통신 방식으로 인해 재현성과

추적성(reproducibility and traceability)이 제한되는 한계를 지닌다

이러한 문제를 해결하기 위해 본 연구는 Model Context Protocol (MCP) [28]을

채택하였다. MCP 는 Context, EvidenceBundle, VerificationReport 등 핵심

메시지 유형을 버전 관리형 스키마로 정의하여, 재현 가능하고 검증

가능한(reproducible and auditable) 멀티 에이전트 협업 구조를 구현한다. 이를

통해 Retriever–Verifier–Generator 간 문맥 교환이 표준화되고, 동기화

오류(synchronization error) 및 중복 질의(redundant querying) 문제가

효과적으로 완화되었다. EvidenceBundle 의 핵심 메타데이터는 아래와 같다.

     section_ID & page_number: 검색된 정보의 원본 위치를 명시하여

      Verifier Agent 가 사실 의거 확인(Fact-Checking)을 수행한다

     confidence_score: 검색을 수행한 에이전트가 이 증거에 대해

      부여한 확신도를 담아, 다른 에이전트가 정보의 신뢰도를 판단하는 데

      사용된다.

     retrieval_query: 이 정보를 얻기 위해 사용된 실제 검색 쿼리를

      기록하여, 통신 과정의 투명성을 높인다.

이러한 구조화된 정보를 통해 에이전트들은 맥락을 잃지 않고, 정보의 출처와

신뢰도를 바탕으로 의사결정을 할 수 있다

     문서 위치 정보(source_uri) 및 상세 메타데이터를 포함한다.

      Retriever 는 정보 누락 없는 발췌와 정확한 메타데이터 매핑에 대한
      일차적 책임을 진다.

  2. [Step 2] Generator Agent (응답 생성 및 문맥 유지): 전달받은 MCP
     객체만을 유일한 근거로 삼아 답변을 생성한다. Step 1 의 메타데이터를
     기반으로 생성된 답변(response)과 구체적 인용구(citations)가 결합된
     EvidenceBundle 을 출력한다. Generator 는 외부 지식에 의한
     환각(Hallucination)을 배제하고 제공된 문맥 내에서만 답변을 생성할
     책임을 가진다.

     생성하며, 문맥 표류(Context Drift)를 최종적으로 차단할 책임을 진다.

제 5 절 문서 구조화 및 계층적 검색 (Document Structuring and

Hierarchical Retrieval)

기존 문서 이해 시스템인 PubLayNet [34]과 LayoutParser [35]은 시각적 블록

단위로 문서를 구분하였으나, 의미적 계층 구조나 섹션 간 논리 관계를 충분히




                                       20
반영하지 못하였다. Docsray [16]는 이러한 한계를 보완하기 위해 pseudo-TOC

기반 계층적 검색 메커니즘을 제안하였다. 이는 하이브리드 OCR, 레이아웃 파싱,

멀티모달 LLM 세분화를 결합하여 문서의 의미 계층 구조를 추출하고, coarse-

to-fine 단계적 검색(coarse retrieval → fine alignment)을 수행한다. 또한

QueryDoc [16]은 온디바이스 환경에 최적화된 임베딩 기반의 2 단계 계층적

검색(Coarse-to-Fine Dense Retrieval)을 수행하여, 경량화된 자원으로도 관련

섹션과 청크를 효율적으로 선별한다. 이러한 구조는 Docsray [16]+ QueryDoc

[16] 통합형 멀티에이전트 추론 구조로 발전하며, 문서 중심의 고도화된 추론

및 해석 기능을 지원한다.




제 6 절 경량 및 자원 적응형 검색 (Lightweight and Resource-

Adaptive RAG)

제안하는 RAG-MCP 통합 구조의 전처리 및 검색 단계는 Docsray [16] 모듈을

기반으로 한다. Docsray 는 다양한 양자화 스펙(Q4/Q8/F16)의 모델들을 지원하며

온디바이스(On-device) 환경에서 작동할 수 있도록 설계되었으며,

FAST/STANDARD/FULL 모드로 시스템 자원 사용량에 따라 처리 전략을 자동

조정한다. Docsray 의 주요 기능은 다음과 같이 구성되어, 본 연구의 자원

적응형 에이전트 스케줄링(Resource-Adaptive Scheduling) 설계의 핵심 구성

요소로 작용한다.

(1) 시스템 자원 기반 적응형 성능 최적화: DocsRay 는 GPU/CPU/MPS 자동 감지

및 psutil 을 통한 가용 메모리 실시간 모니터링을 수행한다. 이 정보를

바탕으로 리소스 제약에 따라 LLM 의 양자화 및 토큰 길이를 동적으로 선택하는

성능 모드를 결정한다.

     FAST_MODE (메모리<16GB): Q4 양자화 모델 및 8K/16K 토큰 길이를

      선택하여 최소 자원으로 빠른 응답 속도를 확보한다.


                             21
     FULL_FEATURE_MODE (메모리>24GB): F16 모델 및 32K 토큰 길이를

      활용하여 최대 성능과 긴 문맥 추론 능력을 제공한다.

(2) 범용 문서 변환 및 전처리: Docsray 는 30 종 이상의 문서 포맷(Office,

텍스트, 웹, 이미지 등)을 자동으로 인식하고 변환할 수 있다. 변환 엔진

관리부는 LibreOffice, Pandoc 등 다중 엔진의 우선순위를 관리하며, 변환 실패

시 다음 우선순위 엔진을 자동 시도하는 폴백 메커니즘을 구현하여 전처리

과정의 강건성(Robustness)을 보장한다.

(3) 하이브리드 OCR 및 시각적 분석: 문서 내 비정형 데이터 및 복잡한

레이아웃에 대응하기 위해 하이브리드 OCR 및 시각적 분석이 통합되었다.

     페이지 복잡도 분석: 텍스트 블록 위치 추출, 다단 레이아웃 감지(KMeans

      클러스터링), 이미지 및 벡터 그래픽 비율 계산 등을 통해 페이지의

      복잡도를 정량적으로 분석한다.

     OCR 선택 실행: 단순 텍스트 레이아웃은 Tesseract 기반 OCR 을 실행하며,

      복잡한 레이아웃이나 시각적 요소가 많은 문서는 Gemma-3-4B 기반의

      멀티모달 OCR 로 보강하여 텍스트 재구성의 정확도를 높인다. 특히,

      시각적 콘텐츠 분석 모듈은 최소 100x100 픽셀 이상의 이미지를 추출하고,

      페이지 내 모든 시각 요소를 병합한 후 멀티모달 LLM 을 통해 차트, 도표,

      다이어그램 등의 의미론적 해석을 생성하여 검색 메타데이터로 활용한다.



Docsray 는 각 섹션별 문맥 정보를 ① 고유 ID, ②Page 번호, ③ 의미론적

경계를 파악한 콘텐츠 구조 형태로 체계적으로 구조화한다. 콘텐츠 구조를

단순히 텍스트뿐만 아니라, 해당 섹션의 제목 수준(H1, H2), 텍스트 본문,

시각화 자료(표/이미지)의 캡션 및 내용을 구분하여 객체 형태로 분리하고

저장한다. QueryDoc (Docsray 의 검색 모듈)[16]은 기존 RAG 시스템이 임베딩

검색을 위해 고성능 클라우드 서버(예: Vector DBaaS)에 의존하는 것과 달리,

제 7 절 점진적 도메인 적응 (Progressive Domain Transfer System:

PDTS)

PDTS [14]는 출처 데이터에 대한 지도학습 이후, 타깃 데이터에서 불확실도

기반 자기학습을 점진적으로 수행하는 메커니즘이다. 본 연구에서는 이를 증거

선택(evidence selection) 문제에 적용하여, Verifier 가 신뢰도 높은

섹션·청크 쌍을 점진적으로 학습 데이터로 채택함으로써, 도메인 적응성과

검증 안정성을 동시에 확보하였다.

단위의 평가와 CCS 기반 보수적 검증을 강조한다. 본 연구의 평가 또한 이러한

데이터셋을 기반으로 설계되어, 장문 문서 이해 및 다중모달 추론 능력을

정량적으로 검증하였다.

제 1 절 연구 설계 개요 (Method / Design Motivation)

본 연구는 RAG(Retrieval-Augmented Generation) [1], [8], [11]와 MCP(Model

Context Protocol) [28]를 결합한 멀티에이전트 기반 객체지향 프레임워크를

제안한다.

이 시스템은 검색–재정렬–동기화 파이프라인을 통합하여 다중 에이전트 간 문맥

정합성(coherence)과 시간적 일관성(synchronization fidelity)을 보장한다.

MCP 는 외부 도구 및 LLM 에이전트 간 표준화된 컨텍스트 교환 프로토콜로,

의미적 표류(semantic drift)를 최소화하고 증거 정합성을 향상시킨다 [28].

이를 통해 general multi-agent reasoning 수준의 추론 과정에서 프로토콜 기반

협업 구조를 실현한다.



제 2 절 프레임워크 설계 (Framework Design)

본 연구에서 제안하는 RAG–MCP 기반 멀티 에이전트 프레임워크는 ① Multi-

Agent Controller, ② 멀티모달 추출(Docsray [16]), ③ Retriever (QueryDoc

[16]), ④ Context Agent (MCP [28]), ⑤ Summarizer, ⑥ LLM Responder 의 6 개

모듈로 구성된다. 각 모듈은 문서 추론의 정확도와 투명성을 높이기 위해

다음과 같은 구조화된 에이전트 구성을 활용합니다. Docsray 모듈 (Retriever &

Preprocessor): Docsray 는 문서 처리 및 검색을 총괄하며, 그 기능은 두 단계로

나뉩니다.

   1. 문서 구조화 및 멀티모달 분석: 하이브리드 OCR 및 트랜스포머 기반 시각

      분석을 통해 레이아웃, 그래프, 표, 차트 캡션 등 멀티모달

      단서(Multimodal Cues)를 추출하여 문서 구조를 파악한다. [34], [35].

   2. 계층적 검색: 추출된 문서의 계층적 유사도(Pseudo-TOC)를 기반으로 관련

      섹션을 일차적으로 식별하며, 이어서 QueryDoc 기반의 정밀 재정렬을

      수행하여 최적의 청크 후보군을 선별한다.

Context Agent (MCP Controller): Context Agent 는 Model Context

제 3 절 의사 목차 기반 계층적 검색 (Pseudo-TOC–Based

Hierarchical Retrieval) (Adapted from Docsray [16])

긴 문서에서 발생하는 구조적 비일관성(structural inconsistencies) 문제를

해결하기 위해, 본 논문은 Docsray [16]에서 제안된 의사 목차(Pseudo-Table-

of-Contents, Pseudo-TOC) 기반의 비학습 구조 추론 방법(training-free

structural inference method)을 활용한다. 이 접근 방식은 기존의 시각적

마커(visual markers)에 의존하는 전통적인 레이아웃 분석과 달리, 대규모 언어

모델(LLM)의 의미론적 추론 능력을 활용하여 문서의 논리적 계층 구조를

구축한다. 이 과정은 의미 분할(semantic segmentation), 구조 정제(structural

refinement), 계층적 검색(hierarchical retrieval)의 세 단계로 구성된다.




                               30
(1) 1 단계: 의미 경계 탐지 및 분할 (Semantic Boundary Detection

and Segmentation)

시스템은 먼저 문서를 고정 크기의 텍스트 청크(fixed-size text chunks)로

분할한다. 주제 간의 논리적인 경계(logical breaks)를 식별하기 위해, LLM

기반 경계 탐지기(LLM-based boundary detector)가 인접한 청크 간의 전환을

분석한다. 구체적으로, 모델은 이전 청크의 끝부분 텍스트와 현재 청크의 시작

부분 텍스트를 비교하여 의미 연속성(semantic continuity)을 평가한다. LLM 은

이 평가를 통해 주제 전환이 발생했는지 여부를 판별(이진 분류)하며, 시각적

서식 단서와 독립적으로 초기 의미 경계 집합을 생성한다.

(2) 2 단계: 적응형 병합 및 제목 생성 (Adaptive Merging and Title

Generation)

초기 분할된 세그먼트들은 검색 효율성을 보장하기 위해 크기 제약 기반 병합

프로세스(size-constrained merging process)를 거친다. 최소 토큰 임계값보다

작은 세그먼트들은 코사인 유사도(cosine similarity)를 기반으로 인접 섹션과

병합되며, 각 구조 단위가 충분한 의미론적 문맥(semantic context)을

유지하도록 보장한다. 섹션이 최종 확정되면, LLM 은 각 섹션에서 대표적인

콘텐츠를 샘플링하여 간결하고 설명적인 제목을 생성한다. 이 메커니즘은

문서의 서사 흐름(narrative flow)을 매핑하는 계층적 색인(Pseudo-TOC)을

생성하는 결과로 이어진다.

(3) 3 단계: 듀얼 임베딩 기반 계층적 검색 (Dual-Embedding

Hierarchical Retrieval)

검색 정확도를 최대화하기 위해 듀얼 임베딩 아키텍처(Dual-Embedding

Architecture)가 활용된다. 이 아키텍처는 두 가지 개별 모델, 즉 밀집




                           31
검색(dense retrieval)을 위한 BGE-M3 와 폭넓은 의미론적 뉘앙스(broader

semantic nuances)를 위한 Multilingual-E5-Large 의 임베딩을 결합한다.

검색은 Coarse-to-Fine(거친 검색 후 정밀 검색) 방식으로 실행된다.

     Coarse Search (거친 검색): 쿼리(질문)가 섹션 수준의 표현과 먼저

      매칭되어 상위 k 개의 관련 섹션을 식별한다.

     Fine Search (정밀 검색): 이후 시스템은 선택된 섹션 내의 개별 텍스트

      청크를 대상으로 정밀 검색을 수행한다.

      이러한 계층적 접근 방식은 검색 복잡도를 O(N) (모든 청크 스캔)에서

      O(S + k 〮
              Ns) 수준으로 크게 줄여(여기서 S 는 섹션 수, Ns 는 섹션당

      평균 청크 수), 재현율(recall)을 희생하지 않으면서도 지연

      시간(latency)을 획기적으로 개선한다.




          [그림 6] pseudo-TOC 계층적 검색 파이프라인 개요 (Adapted from Docsray [16])

Docsray [16] 의사 목차(Pseudo-TOC) 기반 계층적 검색은 3 단계 협력 프로세스로 구성된다: (1)

LLM 경계 탐지를 통한 문서 분할, (2) 적응형 병합 및 제목 생성을 통한 계층적 색인 구축, (3)




                                  32
듀얼 임베딩 아키텍처를 활용한 Coarse-to-Fine 2 단계 검색. 이 방식은 검색 복잡도를 O(N)에서

O(S + k 〮Ns)로 획기적으로 개선하며, 효율성과 재현율을 동시에 향상시킨다.




제 4 절 문맥 일관성 정량 지표 (Context Consistency Score Metrics)

에이전트 간 통신의 신뢰도를 정량적으로 평가하기 위하여,

본 연구에서는 의미적 정합성과 동기화 지연을 동시에 측정하는 문맥 일관성

점수(Context Consistency Score, CCS) [16], [17], [31]를 정의하였다.

         𝐶𝐶𝑆 = 1 · 𝑐𝑜𝑛𝑠𝑖𝑠𝑡𝑒𝑛𝑐𝑦 (𝑄, 𝑅) + 2 · (1 − t_𝑣𝑒𝑟𝑖𝑓𝑦 / t_max)

여기서

     Consistency(Q, R)은 검색된 근거(Q)와 생성된 응답(R) 간의 의미적

      유사도를 의미하며, BLEU, ROUGE-L, 또는 BERTScore 로 측정된다 [31],

      [32].

     𝑡_verify: Retriever 와 Verifier 간의 문맥 동기화 지연 시간을

      나타내며, Δt_max 는 데이터셋별 95% 분위 기준의 최대 지연 허용치이다.

     가중치 계수는 실험적으로 λ₁ = 0.7, λ₂ = 0.3 으로 설정하였다.

이 CCS 지표는 의미적 일관성과 시간적 동기화를 동시에 반영하여, 제안된

멀티에이전트 프레임워크의 재현 가능성(reproducibility) 과

확장성(scalability)을 정량적으로 검증할 수 있다.

     구성: 총 135 개 문서, 1,091 개 질문으로 구성되며, 문서당 평균

     전처리: PDF 파서(OCR+레이아웃 분석)를 통해

     활용: (i) 장문 검색 성능(EM/F1, evidence recall), (ii) cross-page

      retrieval 효율성, (iii) hallucination 억제 성능(Not-answerable

      detection), (iv) modality 별 성능 분석(텍스트/표/차트)을 측정한다.

      스크립트는 외부 LLM 호출을 전제로 하여 재현 비용이 발생한다.

제 1 절 실험 개요

본 장에서는 제안한 RAG–MCP 기반 멀티에이전트 객체지향 프레임워크의 성능을

정량적·정성적으로 검증하고, 각 실험 결과를 해석함으로써 본 연구의 실질적

기여를 논의한다. 실험은 네 가지 공개 데이터셋(arXiv), MMLongBench-Doc [33],

SlideVQA [34], M3SciQA [35])을 대상으로 수행되었으며, 평가 항목은 ① 질의

응답 정확도, ② 문맥 동기화 품질, ③ 자원 효율성, ④ 교차문서 및

교차페이지 추론 ⑤ 모듈 기여도 분석 ⑥ 공개 소스 LLM (Llama-3-70B) 기반

일반화 성능 분석 ⑦ CCS (Context Consistency Score) 가중치 민감도 분석

성능으로 구성되었다. 실험 환경은 Apple M3 Pro(12-core CPU, 14-core GPU, 16-

core Neural Engine, 36 GB unified memory) 기반 macOS 환경이며, GPU 연산은

Metal Acceleration 을 활용한 on-device 방식으로 수행하였다. 별도의 외장

GPU 는 사용하지 않았으며, 난수 시드는 고정하여 모든 결과가 동일 조건에서

반복 가능하도록 하였다.



제 2 절 질의응답(QA) 정확도 평가

(1) 평가 개요

질의응답 정확도는 모델이 제시한 응답의 사실적 일치성과 문장적 유사성을

중심으로 평가하였다 [1], [16]. 평가의 주요 목적은 모델이 제시한 응답의

사실적 일치성(factual consistency)과 문장적 유사성(semantic similarity)을

정량적으로 검증하고, 다양한 벤치마크 환경에서 프레임워크의 구조적 기여를

규명하는 데 있다.

(3) 결과 해석

(가) arXiv

   제안 모델(RAG + MCP, DocsRay-27B)은 F1 기준 85.1%로 LLM Baseline

   대비 +24.3%p 향상된 성능을 보였다. 이는 하이브리드 검색(retrieval)

   전략과 MCP 기반 문맥 동기화(context synchronization)가

   상호보완적으로 작동한 결과로, 검색된 근거 간의 시간적 순서와 논리적

   연계를 유지함으로써 문장적 일관성을 강화한 데 기인한다 [16], [28].

(나) MMLongBench-Doc

   문서 길이와 시각 요소가 혼합된 장문(multimodal long-document)

   환경에서도, 제안 모델의 4B 구성은 F1 65.5%를 기록하여 모든 비교군

   중 최고 성능을 달성하였다. 이는 Retriever 와 Context Agent 간의

   협력적 동기화가 효과적으로 이루어졌음을 의미하며, 문서 내 다중

   페이지 간 맥락 전이를 안정적으로 처리함을 확인하였다. 특히 4B

   모델은 27B 모델 대비 약 35%의 메모리 절감과 낮은 지연시간을




                              46
    달성하면서도 성능 차이는 4~5%p 수준에 그쳐, 비용 대비 효율성(cost-

    to-performance efficiency)이 우수하였다 [33].

 (다) SlideVQA 및 M3SciQA

     두 데이터셋에서는 F1 이 거의 100%에 근접하였으며, 이는 템플릿

     정렬(Label-Tightening)과 텍스트 정규화(Label-Normalization) 과정의

     영향으로 분석된다.

     다만 이러한 완벽에 가까운 결과는 평가 절차상의 구조적 보정 효과에

     의한 것이므로, 모델의 일반화 능력을 그대로 반영한다고 보기는 어렵다.

     이에 본 연구는 해당 결과를 참조 기준(reference baseline)으로

     해석하고, 제 4.6 절 재현성 검증(Verification)에서 별도로 통계 검증을

     수행하였다 [34]

(4) 성능 향상 요인 및 동기화 효과

장문 문맥 추론(Long-Context Reasoning)의 정밀도를 강화하기 위해, 본 연구는

검색-생성 파이프라인의 네 가지 핵심 요소를 개선하였다.

  1. 의사 관련 피드백(Pseudo-Relevance Feedback, PRF) [21] 기반

    하이브리드 검색

    BM25 와 밀집검색(Dense Retriever)을 결합하고, 다중 질의 기반 PRF 를

    적용함으로써 질의의 의미적 범위를 유지하면서도 검색 재현율을 높였다.

  2. 교차 인코더 재랭크(Cross-Encoder Re-Ranking) [26]

    초기 검색 결과 중 실제 답변 가능성이 높은 문서를 재정렬하여, 최종

    문맥 창(Context Window)의 정밀도를 향상시켰다.

  3. MCP 기반 문맥 동기화(Context Synchronization) [28]

    다중 에이전트 간의 근거 정렬 및 문맥 불일치 억제 기능을 수행하여,

    CS-Index 및 Similarity 지표를 높이고 부분 점수형 응답의 안정성을

    개선하였다.


                              47
  4. 하이브리드 요약-추출(Hybrid Summary-Extraction) 디코딩[16].

     문장 수준 요약(best/shortest/longest 전략 병행)을 통해

     다문서·다페이지 환경에서의 누락(omission) 오류를 줄였다.

이러한 개선 요소의 결합을 통해 MMLongBench-Doc 에서

F1 은 51.7%(Baseline)에서 65.5%(RAG+MCP-4B)로 향상되었으며, 메모리 사용량과

지연시간은 오히려 감소하였다. 모든 실험은 고정된 시드(seed)와 해시-안정

80/20 Dev/Test 분할로 수행되었으며, 정확도 검증을 위해 McNemar 검정(EM)과

10,000 회 부트스트랩 순열 검정(F1)을 병행하였다. 이 통계 검증 결과, 성능

향상이 우연적 요인에 의한 것이 아님을 확인하였다.

(5) 종합 논의

이상의 결과를 종합하면, 제안된 RAG + MCP 프레임워크는

① 검색 정확도와 문맥 일관성의 균형을 달성하고,

② 다중 페이지·멀티모달 환경에서도 높은 질의응답 안정성을 확보하였으며,

③ 동일 조건하에서 LLM Baseline 대비 평균 F1 20%p 이상 향상된 결과를

보였다.

특히 MCP 기반 동기화 계층은 단순한 통신 프로토콜을 넘어 에이전트 간 의미적

정합성과 시간적 순서를 조정하는 핵심 인프라로 기능함을 실증하였다. 따라서

본 연구의 QA 성능 평가는 제안 아키텍처가 장문 및 복합 문서 환경에서도

신뢰할 수 있는 추론 능력을 제공함을 보여주는 실증적 근거로 해석된다.

 (1) 평가 지표 정의

문맥 동기화 성능(Context Synchronization Performance)은 문맥 일관성

점수(Context Consistency Score, CCS) [16], [28], [31]를 중심으로

평가하였다.


                                48
본 지표는 (i) 검색 단계에서 확보된 근거(Q)와 생성 응답(R) 간의 의미적

유사도(Semantic Similarity), (ii) 최종 답변이 생성 모듈에 전달되기까지의

엔드투엔드 멀티에이전트 총 동기화 지연 시간 (Δt_sync), 그리고 (iii) 이

둘을 종합한 CS-Index 를 함께 고려하여 산출된다. Similarity 는 시스템 응답과

통합된 검색 근거 집합 간의 ROUGE-L 점수를 기준으로 계산하였으며, 민감도

검증을 위해 BLEU 및 BERTScore 를 보조적으로 사용하였다. CCS 는 검색된

근거(Q)와 생성된 응답(R) 간의 의미적 일관성과 Retriever–Verifier 간 검증

지연 시간을 반영하는 품질 지표이며, CS-Index 는 CCS 를 핵심 요소로 차용하여

입력 질의부터 최종 응답 생성까지의 엔드투엔드 멀티에이전트 총 동기화 지연

시간(Δt_sync)을 통합한 효율성 지표이다.

(3) 결과 해석

 (가) 전반적 동향

       제안한 RAG-MCP 프레임워크는 모든 벤치마크에서 문맥

       일관성(Consistency)과 동기화 효율성(Synchronization Efficiency)을

       동시에 개선하였다. 특히 arXiv 에서는 CS-Index 85.5%로, RAG 단독

       구조 대비 약 +20%p 향상된 결과를 보였다. 이는 MCP 계층이 문맥적

       일관성을 유지하면서 불필요한 정보 중복을 제거하고, 검색–생성 간의

       의미적 드리프트(drift)를 최소화한 결과로 해석된다.

   (나) arXiv 결과

       대형 모델(27B)은 높은 문맥 일관성을 보이는 반면, 메모리 사용량 및


                                 51
   지연시간이 증가하였다. 반면, 소형 모델(4B)은 상대적으로 낮은 지연과

    메모리 요구량으로도 안정적인 동기화 품질을 유지하여, CPU/GPU

    Unified 환경에서도 실시간 처리 가능성을 확인하였다.

 (다) MMLongBench-Doc 결과

    MMLongBench-Doc 의 경우 긴 문서 및 시각적 요소로 인해 동기화

    지연이 평균 88ms 로 다소 증가하였으나, 이는 실시간 질의응답에

    영향을 주지 않는 수준 이었다. 해당 결과는 MCP 가 단순한 통신

    레이어를 넘어 에이전트 간 문맥 일관성(coherence)을 보정·정렬하는

    조정자(regulator)로 기능함을 보여준다. 또한 멀티모달 환경에서도

    안정적인 Alignment 를 유지하여, 의미적 동기화(Semantic

    Synchronization)가 효과적으로 수행되었음을 입증하였다.

  (라) SlideVQA 및 M3SciQA 결과

    두 데이터셋에서는 지연시간이 각각 3.2ms, 3.1ms 수준으로 극히 낮게

    유지되었으며, 이는 텍스트 정규화(Label Normalization)와 응답

    스냅핑(Answer Snapping) 기법의 영향으로 분석된다. 텍스트 기반

    파이프라인에서는 지연과 메모리 사용량이 극소화 되지만, 실제

    RAG+LLM 통합 환경에서는 추가적인 비용(연산 및 전송 지연)이 발생할

    수 있다. 그럼에도 불구하고 제안 프레임워크는 질의응답 품질 저하

    없이 동기화 효율을 유지하였으며, 이는 멀티에이전트 환경에서 문맥

    정합성 유지와 응답 안정성을 동시에 확보할 수 있음을 보여준다.

(4) 종합 논의

    이상의 분석을 종합하면, MCP 계층은 단순한 메시지 전달 계층을 넘어

    문맥적 일관성(Contextual Coherence)을 보장하는 핵심 인프라로

    기능한다.MCP 는 각 에이전트 간의 정보 시점(time-step)과 의미적

    위치(semantic position)를 조정함으로써, 검색–생성 간의 문맥


                          52
       왜곡(contextual drift)을 최소화하였다. 결과적으로 제안된 RAG-MCP

       구조는

       ① 문맥 정렬 품질(Similarity)과

       ② 동기화 효율성(Δt_sync)의 균형을 유지하면서,

       ③ 전체 시스템 수준의 신뢰도(Consistency)를 높였다.

이러한 결과는 MCP 기반 동기화 계층이 지능형 문서 이해 및 협력형 AI

에이전트 시스템의 실시간 문맥 처리(core runtime synchronization)에 있어

중요한 역할을 수행함을 실증적으로 입증한다.

본 절에서는 제안한 RAG–MCP 프레임워크의 자원 효율성(Resource Efficiency)을

정량적으로 평가하였다 [31], [32]. 모든 실험은 MacBook Pro (M3 Pro, 12core

      메모리의 최대 점유치(peak working memory)이다.

     하드웨어 구성(Hardware Architecture)은 CPU 와 GPU 가 통합된 단일

      메모리 구조를 기반으로 하며, Retrieval 과 Generation 모듈이 동일한

제안된 프레임워크는 동일한 조건에서 평균 지연 시간을 단축하면서도 메모리

사용량을 약 3–5% 절감하였다.

(3) 결과 해석

 (가) 전반적 경향

   제안된 RAG–MCP 모델은 단일 구조(RAG-only, MCP module only) 대비

   전반적으로 낮은 메모리 사용량과 안정된 지연시간을 유지하였다. 특히 4B

   구성 모델은 27B 대비 평균 메모리 사용량을 약 40% 절감하면서도, F1 기준

   5% 이내의 성능 차이만을 보였다. 이는 MCP 에이전트가 문맥 확장

                                55
  제한(context pruning) 및 중복 제거(redundancy reduction)를 수행하도록

  설계된 결과로, 연산 효율 향상에 직접적으로 기여하였다.

 (나) arXiv 결과

  Proposed (RAG+MCP, 4B) 모델은 CPU–GPU Unified 환경에서 실행되었음에도

  불구하고, Full GPU 기반 LLM Baseline 대비 약 3~5%의 GPU 메모리 절감과

  유사한 응답속도를 유지하였다. Retrieval 및 Summarization 모듈을

  CPU 에서 처리하고, Decoding 만 GPU 에서 수행하는 구조는 고가 GPU 장비

  없이도 고성능 질의응답을 가능하게 하였다.

 (다) MMLongBench-Doc 결과

  MMLongBench-Doc 의 경우 입력 길이와 시각 정보가 복합되어 처리 지연이

  다소 증가하였으나, 모델 규모별 효율성 비율은 동일하게 유지되었다. 특히

  4B 구성은 27B 대비 메모리 절반 수준으로 동일 성능을 유지하며,

  온디바이스 추론(on-device inference) 에서도 안정적 동작이 가능함을

  보여주었다.

 (라) 자원 효율성의 상대 비교

  27B 구성은 대규모 멀티 GPU 환경에서 더 높은 절대 성능을 기록했으나,

  단일 GPU 또는 제한된 메모리 환경에서는 4B 구성의 효율성이 월등하였다.

  이러한 효율성 차이는 MCP 기반의 문맥 정렬·요약 과정에서 불필요한

  연산량을 줄이는 구조적 최적화 덕분으로 분석된다 [28].

(4) 종합 논의

 종합적으로 볼 때, 제안된 RAG–MCP 프레임워크는

 ① 모델 규모 확장에 따른 자원 사용 효율화,

 ② 통합 연산 환경(On-Device Unified Execution)에서의 실시간 응답성 확보

 ③ 온디바이스 적용 가능성(On-Device Deployability) 측면에서 기존 LLM

(1) 평가 지표 정의

교차문서(Cross-Document) 및 교차페이지(Cross-Page) 추론 성능 평가는 다중

문서 또는 다중 페이지로 구성된 입력 내에서 문맥 연계성과 응답 정확성을

     EM (Exact Match): 모델 응답과 정답 간의 완전 일치율로, 사실적

      정확성(factual precision)을 측정한다.

     F1 Score: 응답 내 주요 토큰 단위의 정밀도와 재현율의 조화 평균으로,

      부분적 정합성(partial correctness)을 반영한다.

     ROUGE-L: 생성된 문장과 기준 문장 간의 문장 수준 유사도(semantic

      overlap)를 평가하여, 모델의 표현적 유창성을 나타낸다.

본 실험에서는 MCP(Model Context Protocol) 기반의 문맥

동기화(synchronization)와 RAG(Retrieval-Augmented Generation) 기반의 계층적

(가) MMLongBench-Doc 의 성능 특성

MMLongBench-Doc 실험에서는 4B 모델이 EM(정답 일치율)에서 우세하였으며,

27B 모델은 F1 과 ROUGE-L 에서 더 높은 값을 기록하였다. 이러한 차이는 모델

규모에 따른 생성 양상 차이에서 기인한다. 대형 모델(27B)은 문장 구조가

풍부하고 표현 다양성이 높아 부분 정합성과 유창성(F1, ROUGE-L)이 향상되지만,

응답이 장문화 되며 불필요한 부연 설명이 포함되어 정확 일치율(EM)은 다소

낮아지는 경향을 보였다. 반면, 4B 모델은 응답이 간결하고 검증 가능한 형태로

생성되어 EM 기준에서 높은 점수를 보였으며, 메모리 사용량이 절반 이하로

줄어드는 등 효율성이 뚜렷하게 나타났다.

(나) SlideVQA 및 M3SciQA 결과

두 데이터셋에서는 정규화된 평가체계(PRF + Label Tightening +

Normalization)가 적용되어 모든 지표에서 F1, ROUGE-L, EM 값이 100%에 근접한

결과를 기록하였다. 이는 평가 환경의 템플릿 정렬(Template Alignment)과 라벨

정규화 효과에 따른 결과로, 모델의 일반화 성능(generalization ability)을

직접적으로 반영하기보다는 상대적 성능 비교(reference benchmark)로 해석하는

것이 타당하다.

(다) MCP 동기화와 계층적 검색의 영향

모든 벤치마크에서 MCP [28] 기반 동기화 계층은 검색 단계에서 확보된 근거

문서 간의 시간적·논리적 순서를 유지하며, 응답 생성 과정에서 문맥

전이(context drift)를 최소화하였다. 특히 교차페이지 추론에서는 하이브리드

검색(Hierarchical Retrieval)과 MCP 동기화(Synchronization)의 결합이 문서 간

참조 관계의 정합성과 응답의 논리적 연계를 강화하였다. MMLongBench-

Doc 에서는 4B 모델이 EM(정답 일치율)에서 더 높은 성능을 보였고,27B 모델은

F1 과 ROUGE-L 에서 우세하였다. 이러한 차이는 모델 규모에 따른 응답 생성

방식의 특성에서 비롯된다. 즉, 대형 모델은 표현의 다양성과 문장 유창성에서

우위를 가지지만, 정확한 포맷 일치에서는 경량 모델이 더 효율적이었다.

SlideVQA 와 M3SciQA 의 높은 점수는 정규화된 평가체계의 영향이 크므로, 이

결과를 절대적 지표로 해석하기보다는 상대적 성능 비교의 참고 자료로 보는

것이 타당하다

보여준다. 즉, Retriever 는 정보 접근의 정확성을 담당하는 모듈로, RAG–MCP

(나) Context Agent 의 영향

15.5%p 급락하였다. 이 결과는 MCP 동기화 계층이 단순한 데이터 전송을 넘어

에이전트 간 문맥 정합성과 시간적 순서를 조정하는 핵심 메커니즘으로

(다) Summarizer Agent 의 영향

Summarizer 제거는 F1 및 CS-Index 모두에서 완만한 하락(평균 −5~8%p)을

보였다.

이는 요약 기능이 사실적 정합성보다는 응답의 문장 유창성(Textual Fluency)과

논리적 연결성(Logical Cohesion)을 강화하는 보조적 역할을 수행하기 때문이다.

따라서 Summarizer 는 응답 품질의 자연스러움을 향상시키며, Retriever–Context

Agent 의 핵심 구조를 보완하는 보조적 모듈로 평가된다.

(4) 종합 논의

모듈 기여도 분석 결과, RAG–MCP 프레임워크의 성능은 세 모듈의 상호보완적

협력 작용(cooperative interaction)에 의해 유지되는 것으로 확인되었다.

  1. Retriever 는 사실 기반 근거 확보의 중심축으로, 제거 시 가장 급격한

     성능 저하를 초래하였다.

  2. Context Agent 는 전역적 문맥 일관성을 조율하는 핵심 역할을

     수행하였으며, MCP 기반 동기화의 효과를 정량적으로 입증하였다.

  3. Summarizer 는 응답의 표현적 완성도와 가독성을 향상시키는

     후처리(post-generation) 단계의 안정화 요소로 기능하였다.

결과적으로, 세 모듈은 각각 Retriever Agent 는 사실성(Factuality), Context

Agent 일관성(Coherence), Summarizer 는 표현력(Fluency)을 담당하며, 이들의

통합적 작동이 제안 프레임워크의 모듈적 견고성(Modular Robustness)과

확장성(Scalability)을 보장한다.

이러한 결과는 RAG–MCP 구조가 단순한 기능적 조합이 아니라, 각 모듈의 역할이

상호 의존적이고 체계적으로 설계된 객체지향형 구조(Object-Oriented

Architecture)임을 실증적으로 보여준다. 따라서 본 프레임워크는 향후 다양한

문서 이해 및 멀티에이전트 기반 응용 시스템으로 확장 가능한 구성적 유연성을

갖춘 것으로 평가된다.



제 7 절 공개 소스 LLM (Llama-3-70B) 기반 일반화 성능 분석

본 프레임워크의 일반화 능력을 검증하고 모델 계열에 걸친 일관성을 확인하기

위해, 공개 소스 모델인 Llama-3-70B-Instruct 모델을 생성기(Generator)로

사용하여 비교 분석을 수행하였다. 실험 설정은 표준 RAG 파이프라인과 제안된

RAG-MCP 프레임워크를 동일한 조건 하에 비교하였으며, 가장 난이도가 높은

장문서 벤치마크(MMLongBench-Doc)에 초점을 맞추었다.<표 10>에 요약된 결과는

공개적으로 사용 가능한 고성능 LLM 에서도 본 접근 방식의 일관성과 효율성이

유지됨을 명확히 보여준다. 표준 RAG 파이프라인은 평균 F1-점수 약 0.56,

일관성 점수 0.64, 평균 지연 시간 2,644 ms 를 기록했다. 반면, 제안된 RAG-

MCP 는 F1-점수 0.77, 일관성 점수 0.87, 평균 지연 시간 1,749 ms 를 달성했다.

제 8 절 CCS (Consistency Confidence Score) 가중치 민감도 분석

제안된 프레임워크의 핵심 요소 중 하나는 검증 에이전트(Verifier Agent)가

사용하는 일관성 인식 신뢰 점수(CCS)이다. CCS 계산은 사실적 일관성 항 λ1 과

지연 시간 기반 효율성 λ2 에 가중치를 부여하며, 본 연구에서는 λ1 = 0.7 및

λ2 = 0.3 으로 설계되었다. 이 가중치 선택에 대한 경험적 정당성을 제공하기

위해 민감도 분석을 수행하였다. MMLongBench-Doc 시나리오를 시뮬레이션하고,

일관성 가중치 λ1 을 0.1 에서 0.9 까지 0.1 단위로 체계적으로 변화시키며

분석을 진행했다. 각 λ1 값에 대해 계산된 CCS 값과 실제 정답 성능(F1-점수)

간의 상관계수를 계산하였다.

분석 결과, 상관계수는 λ1 이 [0.6, 0.8] 범위에 있을 때 최고점을

기록하였으며, 이는 일관성 가중치를 높게 설정하는 것이 실제 성능을 반영하는

데 최적임을 강력하게 시사한다. 특히 λ1=0.7 근처의 높은 상관관계는 현재의

설계 선택이 사실적 일관성을 우선시하면서도 시스템 효율성(지연 시간)이라는

중요한 차원을 통합하는 합리적인 절충안임을 지지한다.

상관관계는 λ1 [0.6, 0.8] 부근에서 최고점을 기록하며, 이는 λ1=0.7 선택을 실증 한다.

정규화 미적용 시 평균 4 ~ 6 %의 성능 저하가 관찰되었다. 이 차이는 평가

제 10 절. 종합 논의 및 시사점

(1) RAG–MCP 통합의 구조적 효과

RAG 와 MCP 의 결합은 기존 RAG 단독 구조 대비 문맥 일관성과 협업 안정성을

현저히 향상시켰다. arXiv 실험에서 F1 기준 +24.3%p LLM Baseline 대비 향상이

확인되었으며, MMLongBench-Doc 에서도 4B 구성 기준 F1 = 65.5%로 높은 성능을

보였다. 이는 하이브리드 검색과 MCP 기반 문맥 동기화의 상호보완 작용으로,

검색된 근거 간의 시간적 순서와 논리적 연계 유지가 응답의 사실성(Factual

Consistency) 향상으로 이어진 결과이다.

(2) 문맥 동기화 계층(MCP)의 실질적 기여

MCP 동기화 계층은 단순한 통신 구조가 아닌 문맥적 정합성을 보정하는

조정자(Regulator)로 기능하였다. 모든 벤치마크에서 CS-Index 는 평균 +15~20%p

개선, arXiv 에서는 85.5%, MMLongBench-Doc 에서는 49.3%를 기록하였다.

이는 MCP[28]가 에이전트 간 의미적 일관성과 시간적 동기화를 유지함으로써

추론 신뢰도를 높였음을 보여준다.

(3) 자원 효율성과 실시간 추론성

4B 모델은 27B 대비 메모리 사용량 40% 절감, 지연시간 유지, 정확도 손실 ≤

5%p 를 달성하였다. 본 연구는 고가 GPU 없이 실시간 문서 추론이 가능한

온디바이스(on-device) 환경 구축을 목표로 하였다. 따라서, 실험 환경(Apple

M3 Pro Unified Memory Architecture)을 활용하여 Retrieval 및

Summarization 을 CPU 에서, Decoding 을 GPU 에서 수행하는 하이브리드 구조를

구현하였다. 이러한 구조적 최적화는 4B 규모의 경량 모델에서도 안정적인

성능을 유지하며, 제안된 RAG-MCP 통합 구조가 고가 GPU 없이도 실시간

질의응답이 가능함을 입증하였다. 이러한 결과는 제안된 경량형 구조가 문서

기반 추론 시스템의 실용적 대안으로 활용될 가능성을 보여준다.

(4) 교차문서·교차페이지 추론

MCP 기반 동기화와 계층적 검색의 결합은 문서 간 참조 정합성을 강화하였다.

MMLongBench-Doc 에서 4B 모델은 EM=44.1%, F1=51.9%, 27B 모델은 F1=65.6%,

     성능 향상: Llama-3-70B 기반 실험에서 표준 RAG 파이프라인 대비 가장

Agnostic) 견고성을 확인하였다.

(7) CCS (Consistency Confidence Score) 가중치 민감도 분석

제안된 핵심 정량 지표인 CCS(Context Consistency Score)의 가중치

설계λ1=0.7, λ2=0.3)에 대한 경험적 정당성을 확보하였다.

     최적 가중치 범위: CCS 와 실제 응답 성능(F1-점수) 간의 상관관계 분석

      결과, 일관성 가중치 λ1 이 [0.6, 0.8] 범위에 있을 때 가장 높은

      상관계수를 기록하였다.

     설계 정당화: 이는 사실적 일관성(λ1)에 높은 가중치를 부여하는 현재의

      설계 선택(λ1=0.7)이 시스템의 실제 추론 성능을 가장 잘 반영하는

      합리적인 절충안임을 실증적으로 지지한다.

이 분석은 CCS 가 단순한 모니터링 지표를 넘어, 멀티에이전트 시스템의 내부

추론 신뢰도와 효율성을 통합적으로 평가하는 엄격하고 타당한 수단임을

확인시켜 준다.

(8) 종합 시사점

본 연구는 “모델의 크기보다 구조적 설계와 문맥 관리 체계가 인공지능 추론

품질을 결정한다”는 사실을 실증하였다.

제 1 절 연구 결과의 요약

본 연구에서는 대규모 언어모델(LLM)의 구조적 한계를 보완하기 위하여,

문서·멀티모달 벤치마크 환경에서 우수한 성능을 보였다. 구체적으로, 제안된

모델은 기존 GPT-RAG 단독 구조 대비 F1 기준 평균 20%p 이상의 성능 향상을

달성하였으며, 문맥 일관성을 나타내는 CS-Index 또한 평균 15~20%p 개선되었다.

아울러, 모델의 효율성 측면에서도 4B 구성 모델이 27B 대비 약 40%의 메모리

사용량을 절감하면서도, 정확도 손실을 최소화하였다. 이와 같은 결과는 MCP

기반 문맥 관리 계층이 에이전트 간의 의미적 일관성과 시간적 정합성을

유지하여 추론 신뢰도를 향상시켰음을 보여준다.

또한 본 연구의 프레임워크는 CPU–GPU Unified 환경에서도 안정적으로 작동하여,

온디바이스(On-Device) 환경에서 실시간 추론을 구현할 수 있음을 실증하였다

[28], [31].

제 3 절 응용 가능 분야

본 연구에서 제안한 RAG–MCP 기반 멀티에이전트 문서형 General Multi-Agent

(1) 법률 및 계약 문서 분석

Docsray [16] 기반의 멀티모달 문서 처리 기능은 복잡한 구조의 계약서나 법률

해석서 분석에 매우 효과적이다. 하이브리드 OCR 을 활용하면 문서 내 시각적

강조 요소(예: 볼드체, 밑줄, 표기 색상 등)를 인식할 수 있고, 계층적 의미

분석을 통해 조항 간 종속 관계나 참조 표현을 자동으로 파악할 수 있다.

이러한 구조는 Multi-Agent 질의응답 체계와 결합되어 대규모 법률 문서에서

핵심 조항을 신속히 식별하고 법적 리스크를 자동으로 탐지할 수 있다. 따라서

법무법인, 기업 법무팀, 공공기관 등에서 계약 검토 자동화와 법령 비교 분석을

지원하는 실무적 도구로 발전할 수 있다.

(2) 의료 및 임상 문서 기반 AI 협업

의료 도메인은 비정형 문서의 대표적인 영역으로, 임상 보고서, 검사 결과지,

방사선 판독서 등은 텍스트와 표, 이미지가 복합적으로 구성된다. Docsray

[16]는 이와 같은 다양한 형식을 멀티모달 벡터로 통합하여 질의 기반 진단

추론, 환자 상태 요약, 약물 상호작용 탐지 등을 수행할 수 있다. 또한 의료


                          71
특화 에이전트와의 협업을 통해 임상결정지원시스템(CDSS)으로 확장될 수

있으며, 의료진의 판단을 보조하는 해석 가능한 AI 도구로 기능할 수 있다.

특히 온디바이스 구조를 적용하면 폐쇄망 병원 환경에서도 개인정보 유출 위험

없이 안정적인 운용이 가능하다.

(3) 교육 및 문서 튜터링 에이전트

Docsray [16]의 하이라이팅 정보와 질의 기반 분석 기능은 교육용 문서 분석에

매우 적합하다. 본 시스템은 교재, 논문, 학습 자료 등에서 핵심 개념을 자동

추출하고, 장과 절 간의 개념적 연결 구조를 시각화 할 수 있다. 이를 기반으로

학습자의 수준에 맞춘 개인 튜터 에이전트를 개발할 수 있으며, 문서 요약,

연습문제 자동 생성, 개념 지도 작성 등 다양한 교육 기술로 발전할 수 있다.

나아가 멀티에이전트 기반 피드백 구조를 도입하면 인간 교사와 AI 에이전트가

협력하여 학습 효율을 극대화하는 지능형 교육 환경을 구현할 수 있다.

(4) 기업 내 문서 기반 RAG 지식베이스

문서형 RAG 와 MCP 기반 컨텍스트 동기화 구조 [28]는 기업 내부의 정책 문서,

기술 사양서, 제품 매뉴얼 등 다양한 문서에서 지식을 추출·공유할 수 있는

자동화된 사내 지식베이스 시스템으로 확장될 수 있다. 복수의 에이전트가 문서

분할, 검색, 요약, 응답 생성을 분담함으로써 방대한 사내 문서 데이터에 대한

실시간 질의응답이 가능하다. 특히 메모리 캐시 구조와 문맥 추적 기능은 버전

관리나 변경 이력이 중요한 IT, 금융, 제조 산업에서 매우 유용하다. 이러한

구조는 기업 내 정보자산의 활용도를 높이고, 분산된 문서 지식의 중앙 집중형

접근을 가능하게 한다.

(5) 멀티모달 에이전트 시뮬레이션 및 강화학습

향후에는 MCP 를 기반으로 문서 외에도 대화, 시각 정보, 센서 데이터 등을

통합하여 멀티모달 강화학습(Multimodal Reinforcement Learning) 환경을




                            72
구축할 수 있다 [28], [31]. 이를 통해 에이전트 간 협력과 경쟁을

시뮬레이션하고, 자율 협상 에이전트, 전략형 게임 AI, 로봇 문서 해석기 등

다양한 응용으로 발전할 수 있다. 이러한 확장은 단순 문서 이해를 넘어,

실시간 의사결정과 행동계획을 수행하는 지능형 에이전트 연구로 이어질 것이다.



제 4 절 연구의 한계

본 연구는 제안된 프레임워크의 가능성을 실증적으로 입증하였으나, 여전히 몇

가지 한계가 존재한다.

(1) 데이터 다양성의 한계

  웹 문서, 코드, 스트리밍 데이터 등 다양한 데이터 형식에 대한 일반화

  가능성은 추가 검증이 필요하다.

(2) 임베딩 모델 변화에 따른 검색 정밀도의 동적 조정 필요성

  Docsray [16]는 모델 교체의 유연성을 높이고 하드웨어 환경에 적응하도록

  설계된 시스템이지만, 검색 성능 최적화를 위해 특정 임베딩 모델(BGE-M3,

  E5-Large 등)을 모듈화 하여 결합하고 있어, 해당 임베딩 모델 업데이트 시

  검색 성능의 재검증이 필요할 수 있다.

(3) 평가 체계 제한점

  본 연구의 평가 지표는 QA 정확도, 문맥 정합성, 자원 효율성에 집중되어

  있어 실제 응용 환경에서 중요한 사용자 경험(UX)과 확장성(Scalability)이

  충분히 평가되지 않았다 [31], [33].

(4) 산업 적용을 위한 보안·규제 요인의 미반영

  산업적 활용을 위해 중요한 데이터 보안, 개인정보 보호, 규제 준수 등의

  현실적 제약 요인이 반영되지 않아 실제 배포 환경에서 요구되는 제한

  조건을 충분히 고려하지 못했다.




                        73
(5) 문서 이해·추론 능력의 구조적 한계

   본 연구가 제안한 시스템은 문서 이해 및 문맥 관리 능력에서 여전히

   제한이 존재하며, 자율적 목표 설정과 장기적 추론을 포함한 완전한

   General multi-Agent reasoning 수준으로 도약하기 위한 핵심 능력은

   충분히 확보되지 않았다 [1], [28].



제 5 절 향후 연구 방향

향후 연구에서는 제안된 프레임워크가 범용 멀티에이전트 추론(General Multi-

Agent Reasoning) 시스템의 실질적 구현 기반이 될 수 있도록 구조적 확장과

기능적 고도화를 지속적으로 추진할 예정이다. 주요 연구 방향은 다음과 같다.

(1) 다양한 문서 유형으로의 확장

현재 시스템은 PDF 기반의 비정형 문서를 중심으로 설계되었으나, 향후에는 웹

문서, 소스 코드, 스트리밍 데이터, 멀티미디어 문서 등 보다 다양한

형식으로의 적용 가능성을 검토할 예정이다. 이를 통해 제안된 문서 이해·추론

구조가 다양한 데이터 환경에서도 일관된 문맥 동기화를 유지할 수 있는지를

평가하고, 시스템의 활용 범위를 체계적으로 확장할 수 있을 것으로 기대된다

(2) 경량화 및 온디바이스 최적화

LoRA, QLoRA, 지식 증류(Knowledge Distillation) 등의 최신 경량화 기법

[31]을 적용하여, 일반 GPU 나 모바일 디바이스에서도 실행 가능한 온디바이스

General Multi-Agent Reasoning 프로토타입을 구현할 예정이다. 이러한 접근은

클라우드 기반 고성능 처리에 의존하지 않고, 비용 절감과 빠른 응답성,

개인정보 보호를 동시에 달성할 수 있는 실시간 AI 실행 구조를 구축하는 데

초점을 둔다. 또한 WebAssembly(WASM) 및 ARM 아키텍처 기반 최적화 모듈을

적용하여 저전력 환경에서도 효율적인 추론을 지원할 것이다.




                             74
(3) 도메인 특화 General Multi-Agent Reasoning 시스템 개발

Docsray [16] 기반 구조를 활용하여 특정 산업에 최적화된 General Multi-Agent

Reasoning 시스템 [17], [33]을 개발할 예정이다. 법률 분야에서는 복잡한 규칙

기반 추론이 필요한 판례 및 법령 해석을 자동화하고, 의료 분야에서는

멀티모달 의료 리포트를 분석하여 진단 보조 시스템을 구축할 수 있다. 또한

정책·행정 분야에서는 공공 문서 및 정책 보고서를 기반으로 한 자동 분석 및

응답 시스템을 개발하여 행정 효율화를 도모할 수 있다.

(4) 비동기 및 분산형 에이전트 협업 구조 연구

에이전트 간 시간차가 존재하는 비동기적 환경에서도 문맥의 연속성과 일관성을

유지하기 위한 새로운 협업 프로토콜을 설계할 예정이다. 다중 사용자 간 문서

공유와 질의응답 상황을 시뮬레이션하여 협력적 인공지능 시스템의 실시간 협업

능력을 검증하고, 대규모 분산형 General Multi-agent Reasoning 환경으로의

확장을 모색한다.

(5) 평가 지표의 고도화

BLEU, ROUGE, BERTScore 와 같은 기존 정량 지표 외에도 인간 평가(Human

Evaluation), 행동 로그 기반 분석(Action Traceability), 사용자 경험(UX)

기반 확장성 평가 등을 포함하는 다차원 벤치마크 체계를 구축할 계획이다.

이를 통해 General Multi-agent Reasoning 의 실용성과 해석 가능성을 동시에

측정할 수 있는 표준화된 평가 체계를 마련할 것이다 [31], [33].

(6) 연합학습 기반 보안 강화형 General Multi-Agent Reasoning 연구

기업이나 기관 내부 문서를 다루는 General Multi-Agent Reasoning 시스템의

특성상, 중앙집중형 학습 방식은 보안과 개인정보 보호 측면에서 한계를 가진다.

따라서 연합학습(Federated Learning), 차등 개인정보 보호(Differential

Privacy) [31], 다자간 암호화(MPC) 기술을 결합하여 보안 강화형 협력 학습




                             75
구조를 구축할 예정이다. 이를 통해 실제 산업 환경에서도 신뢰할 수 있는

데이터 보호형 General Multi-Agent Reasoning 시스템을 실현하고자 한다.

(7) General multi-Agent Reasoning 수준으로의 확장

마지막으로, 문서 기반 질의응답을 넘어 에이전트가 스스로 목표를 설정하고

계획을 수립하며 장기적 멀티스텝 추론을 수행할 수 있는 자율형 General

Multi-Agent Reasoning 로의 발전을 목표로 한다. 이는 단순한 정보 검색형

인공지능을 넘어, 인간의 사고 과정에 근접한 협업형·인지형 General Multi-

Agent Reasoning 로 진화하기 위한 핵심 연구 방향이 될 것이다 [28], [33].

이와 같이, 본 연구의 응용 가능성과 한계, 그리고 향후 발전 방향은 RAG–MCP

기반 멀티에이전트 구조가 실질적 General Multi-agent Reasoning 구현을 위한

핵심적 전환점이 될 수 있음을 보여준다. 향후 연구는 본 프레임워크를

중심으로 다양한 도메인에 적용 가능한 확장형 지능 시스템을 구축함으로써,

문서 중심 협업형 인공지능(Document-Centric Collaborative Intelligence)의

새로운 패러다임을 제시할 것이다.

        부록 B. SlideVQA·M3SciQA 보수적검증

          (Conservative Verification) 절차
본 부록은 SlideVQA 와 M3SciQA 데이터셋 평가에서 기존 템플릿 기반 정규화

절차로 인해 발생하는 상한 효과(ceiling effect)를 보정하고, 실제 문맥 기반

추론 능력을 평가하기 위해 적용한 보수적 검증(Conservative Verification)

절차를 자세히 기술한다. 템플릿 기반 평가가 기계적 문자열 비교에 과도하게

의존한다는 한계점을 보완하고, 모델이 산출한 응답이 문맥적으로 타당한지

평가하기 위해 추가적인 의미 기반(sementic) 검증 방식을 적용하였다.



B.1 보수적 검증 개요

보수적 검증은 단순한 문자열 비교를 넘어 자연어 기반 의미 정합성 평가를

중심으로 설계되었다. 평가 과정은 크게

① 정규화 단계,

② 라벨 매핑 단계,

③ 의미 기반 평가 단계,

④ 결과 안정성 검증 단계로 구성되며,

각 단계는 모델 응답이 실제 문맥을 반영하고 있는지, 그리고 사람이 판단했을

때의 정답과 자연스럽게 일치하는지를 확인하기 위한 절차로 구성되어 있다. 이

방식은 기존 템플릿 기반 점수체계에서 나타나는 ‘기계적 일치 점수 상승’

문제를 완화하며, 특히 복잡한 슬라이드·과학기술 도메인에서 요구되는 문맥적

이해 능력(context-grounded reasoning)을 보다 정밀하게 평가하는 것을 목표로

한다.

점에서 실제 reasoning 성능을 가장 정확하게 반영한다.



B.3 보수적 검증 절차

보수적 검증은 다음과 같은 다단계 절차로 수행하였다.

(1) 정규화 단계

모델 응답(Pred)과 기준 정답(GT)에서

     구두점 제거

     대소문자 통일

     불용어(stopword) 제거




                                96
     단위 표기 정규화

를 수행하여 언어적 잡음(noise)을 최소화하였다.

(2) 자연 라벨 매핑 단계 (Label Mapping)

정규화된 예측값과 정답을 비교할 때, 단순 토큰 일치가 아닌 자연스러운 의미

매칭을 적용하였다.

예)

     “accuracy (%)” ↔ “model accuracy”

     “param count” ↔ “number of parameters”

     “slide index” ↔ “page ID”

이 라벨 매핑은 사람이 검증한 자연 표현에 기반해 구축되었으며, 이는 템플릿

기반 정답 키가 가진 인위적 표현과 실제 사람이 쓰는 표현 간의 괴리를

보완하기 위한 것이다.

(3) 의미 기반 평가 단계

정규화 및 라벨 매핑 후에는 다음 지표를 활용하여 의미 정합성을 평가하였다.

     Semantic F1

     ROUGE-L (Longest Common Subsequence 기반 문맥 유사도)

     BERTScore (의미 임베딩 기반)

이러한 지표는 단순한 토큰 일치와 달리 문장적 유사도 및 문맥적 근접성을

평가하므로, 슬라이드·논문·과학적 문서처럼 표현이 다양하고 서술형 응답이

많은 환경에서 더욱 타당하다.

(4) 결과 안정성 검증 단계 (Robustness Check)

보수적 검증 결과의 신뢰도를 확보하기 위해 다음과 같은 안정성 검증을

병행하였다.

     랜덤 시드 변경 후 재평가 (N=10)



                                97
     BERTScore threshold ≥ 0.8 응답만 포함



     응답 길이 변화에 대한 민감도 확인

이를 통해 단순 문자열 변화로 인한 평가 편차를 제거하고, 평가 결과의 통계적

안정성을 확보하였다.

B.5 종합 해석

보수적 검증 결과, 두 데이터셋 모두 템플릿 기반 평가보다 10–19 p.p. 낮은

성능을 보였다. 이는 기존 평가체계가 지나치게 기계적 정규화에 의존함으로써

실제 reasoning 능력을 과대평가했음을 의미한다. 그러나 주목할 점은, 제안된

RAG–MCP 27B 모델은 보수적 평가에서도 여전히 최고 성능을 보였다는 점이다.

즉, 고정된 정규화 절차 없이도 실질적인 문맥 추론 능력이 우수했음을

의미하며, 이는 멀티에이전트 기반 MCP 동기화의 효과가 단순한 패턴 매칭을

넘어 의미적 연결성을 보정한다는 점을 보여준다.

C.8. Hybrid Retriever (Dense + Lexical) 코드

본 연구의 Retriever 는 Dense 임베딩(E5)과 BM25 기반의 Lexical 검색 점수를

결합하는 구조로 구성된다.

# retriever.py



import numpy as np



                                     103
from sentence_transformers import SentenceTransformer

from sklearn.feature_extraction.text import TfidfVectorizer

from mcp_protocol import ContextMessage, EvidenceBundle



class HybridRetriever:

    def __init__(self, corpus, toc_index=None):

        self.corpus = corpus

        self.encoder = SentenceTransformer("intfloat/e5-base")

        self.vectorizer = TfidfVectorizer()

        self.bm25_matrix = self.vectorizer.fit_transform(corpus)

        self.corpus_emb = self.encoder.encode(corpus,

convert_to_numpy=True)

        self.toc_index = toc_index



    def retrieve(self, query, topk=5):

        msg = ContextMessage(qid=str(uuid.uuid4()), query=query)



        q_emb = self.encoder.encode([query], convert_to_numpy=True)[0]

        dense_scores = np.dot(self.corpus_emb, q_emb)



        bm25_scores = self.bm25_matrix.dot(

            self.vectorizer.transform([query]).T

        ).toarray().ravel()



        final_scores = 0.5 * dense_scores + 0.5 * bm25_scores



                                     104
        idx = np.argsort(final_scores)[::-1][:topk]

        evidence = [self.corpus[i] for i in idx]



        return msg, EvidenceBundle(msg.qid, evidence,

final_scores[idx].tolist())

C.10. QueryDoc [16] 기반 재정렬(Re-ranking) 모듈

Retrieval 이후, 쿼리 조건 기반의 재정렬을 수행하는 모듈이다.

# querydoc_pipeline.py



import numpy as np

from sentence_transformers import SentenceTransformer



class QueryDoc Internal Specification (2025)Reranker:

    def __init__(self):

          self.encoder = SentenceTransformer("mixedbread-ai/mxbai-embed-

large")



    def rerank(self, query, evidence_list):

          q = self.encoder.encode([query])[0]

          E = self.encoder.encode(evidence_list)



          scores = np.dot(E, q)

          idx = np.argsort(scores)[::-1]

          return [evidence_list[i] for i in idx], scores[idx]

C.11. Verifier 모듈 (CCS 계산 + PDTS 형태 검증)

Verifier 는 Evidence 와 응답 간의 의미적 일관성을 측정하여 CCS(Context

Consistency Score)를 계산한다.

# verifier_agent.py



import numpy as np

from sentence_transformers import SentenceTransformer

from mcp_protocol import VerificationReport



class Verifier:

    def __init__(self, ccs_weight=0.6, threshold=0.65):

        self.encoder = SentenceTransformer("intfloat/e5-base")

        self.ccs_weight = ccs_weight

        self.threshold = threshold



    def compute_similarity(self, evidence, answer):

        ev_emb = self.encoder.encode([" ".join(evidence)])

        ans_emb = self.encoder.encode([answer])

        return float(np.dot(ev_emb, ans_emb.T))



    def compute_latency_factor(self, latency_ms):

        return max(0.0, 1 - latency_ms / 2000)



    def verify(self, bundle, answer, latency_ms=50):

        sim = self.compute_similarity(bundle.evidence, answer)



                                     107
        time_factor = self.compute_latency_factor(latency_ms)

        ccs = self.ccs_weight * sim + (1 - self.ccs_weight) * time_factor

        decision = "OK" if ccs >= self.threshold else "REFINE"

        return VerificationReport(bundle.qid, float(ccs), decision)



C.12. 평가 스크립트 (EM, F1, ROUGE-L, CS-Index)

# evaluate.py



from rouge_score import rouge_scorer

from sklearn.metrics import f1_score

from utils import normalize_text

from verifier_agent import Verifier



def evaluate(gold, preds, evidences):

    scorer = rouge_scorer.RougeScorer(['rougeL'], use_stemmer=True)

    verifier = Verifier()

    results = []



    for g, p, ev in zip(gold, preds, evidences):

        em = int(normalize_text(g) == normalize_text(p))

        f1 = f1_score(list(g), list(p), average='micro') if g and p else 0

        rouge = scorer.score(g, p)['rougeL'].fmeasure

        ccs = verifier.compute_similarity(ev, p)



        results.append({"EM": em, "F1": f1, "ROUGE-L": rouge, "CCS": ccs})



                                      108
    return results



C.13. MCP 메시지 로그 재생(Replay) 도구

# replay_mcp_logs.py



import json

import time



def replay(log_path):

    with open(log_path, "r") as f:

        logs = [json.loads(line) for line in f.readlines()]



    for entry in logs:

        print(f"[{entry['msg_type']}] QID={entry['qid']}")

        print(json.dumps(entry, indent=2))

        time.sleep(0.1)



    print("Replay completed.")
